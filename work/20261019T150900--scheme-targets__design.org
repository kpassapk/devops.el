#+TITLE: Scheme targets: a CLI's credential as a #+TARGET
#+PROPERTY: header-args:sh :results output
#+TARGET: local ..

* Background

A =#+TARGET= is a place: a directory or a TRAMP prefix, injected as
=:dir=. But much of what an operator reaches with credentials is not a
filesystem: an AWS service, a kube deployment, a =gh= account, a
=PGSERVICE=. Today a block picks those itself (=aws --profile prod …=),
so nothing about the heading says which credential it uses, and
nothing stops a block from naming another one.

TRAMP already covers containers and pods as filesystems
(=/ssh:host|podman:box:=, =/kubernetes:pod:=), so those stay as they
are. This is for the rest.

The driver is devops.bb's sandbox work: Claude, in a sandbox, writes
the workbook, and the operator runs it. There, a target is a
credential, the prompt shows which one a block will use, and the
operator, not the workbook, decides which ones a workbook may name.

* Spec

** Goal

- =#+TARGET: prod /aws:prod:= makes the blocks under =:prod:= run with
  the credential context =aws:prod=, chosen through the environment.
- The body runs unchanged: several commands, pipes, loops, =aws= and
  =jq= and =kubectl= mixed.
- What a scheme means is set in the operator's Emacs, never in the
  workbook, with an allowlist per scheme.
- =devops-open-terminal-dwim= opens a terminal with the same
  environment.

** Why environment, not a prefix

Interpolating a prefix (=aws --profile prod <<BLOCK>>=) works for a
one-command body only. With a pipe it applies to the first word,
quoting breaks, and the text that runs is neither what was written nor
what the operator read. The CLIs already pick credentials from the
environment: =AWS_PROFILE=, =KUBECONFIG=, =GH_CONFIG_DIR=,
=PGSERVICE=, =CLOUDSDK_ACTIVE_CONFIG_NAME=. A scheme target sets those
for the session, and the body is left alone.

** Syntax

=/SCHEME:ARG:=, a TRAMP-like name that is not TRAMP: SCHEME is a key of
=devops-target-schemes=, ARG a name, =[[:alnum:]][[:alnum:]_-]*= (no
=.=, no =/=, so =%s= in a path cannot climb out). It is recognized
before any TRAMP call: a scheme name must never reach
=expand-file-name=, =file-remote-p= or =tramp-dissect-file-name=, whose
file name handlers would try =aws= as a TRAMP method (step 1 checks
what each does with one). A name whose SCHEME is not in the map is
left to TRAMP as today.

** The map

#+begin_src emacs-lisp :eval no
(defcustom devops-target-schemes nil
  "Schemes a #+TARGET may name as /SCHEME:ARG:, for non-filesystem targets.
Each entry is (SCHEME . PLIST):

  :env    alist of (NAME . FORMAT); FORMAT's %s is ARG, and a value
          starting with ~/ is expanded.  Set in the session's
          environment when it starts.
  :unset  list of NAMEs removed from the environment Emacs passes on,
          the variables that would take precedence over :env.
  :allow  list of the ARGs a workbook may name, or nil for any ARG
          matching the name syntax.
  :dir    directory the blocks run in, relative to the project root,
          or nil for the project root itself.  Outside a project the
          root is the org file's directory."
  :type '(alist :key-type string :value-type plist)
  :group 'devops)

(setq devops-target-schemes
      '(("aws"  :env (("AWS_PROFILE" . "%s"))
                :unset ("AWS_ACCESS_KEY_ID" "AWS_SECRET_ACCESS_KEY"
                        "AWS_SESSION_TOKEN" "AWS_DEFAULT_PROFILE")
                :allow ("dev" "staging" "prod"))
        ("kube" :env (("KUBECONFIG" . "~/.kube/%s.yaml")))
        ("gh"   :env (("GH_CONFIG_DIR" . "~/.config/gh-%s"))
                :unset ("GH_TOKEN" "GITHUB_TOKEN" "GH_ENTERPRISE_TOKEN"
                        "GITHUB_ENTERPRISE_TOKEN" "GH_HOST"))
        ("pg"   :env (("PGSERVICE" . "%s"))
                :unset ("PGHOST" "PGHOSTADDR" "PGPORT" "PGUSER"
                        "PGPASSWORD" "PGDATABASE" "PGPASSFILE"))))
#+end_src

=:allow= is what makes this safe when someone else writes the workbook:
=/aws:prod-admin:= fails with =user-error "Target prod: aws:prod-admin
is not in :allow"= before anything runs.

*=:unset= keeps the label true.* The scheme's =:env= goes in front of
the environment Emacs inherited, and most CLIs let *other* variables
win over the one a scheme sets: AWS's env keys over =AWS_PROFILE=,
=GH_TOKEN= over =GH_CONFIG_DIR=, =PGHOST= / =PGUSER= over
=PGSERVICE=. Emacs picks these up easily (=envrc=,
=exec-path-from-shell=, a shell with an =aws sso= export). Without
=:unset= the block runs as whatever identity those hold while the
target, and devops.bb's prompt, say =AWS_PROFILE=prod=. Explicit per
scheme, not guessed from a prefix: the precedence rules are each CLI's
own. The example above is the README's and the docstring's; it is the
part worth copying.

** Resolution

- =devops--parse-target-keyword= is unchanged: =/aws:prod:= is already
  one word.
- A new =devops-target-scheme TARGET= returns =(SCHEME ARG PLIST)= for a
  scheme target, or nil. It checks the name syntax and =:allow=.
- Dynamic targets compose: =#+TARGET: prod <<assume-role()>>= may yield
  =/aws:prod:=, and is checked the same way after it resolves.
- =devops-target-env TARGET= returns the expanded =(NAME . VALUE)=
  alist, public, for a package that shows it, with each =:unset= NAME
  as =(NAME . nil)= after the =:env= pairs (devops.bb's confirm prompt:
  =target /aws:prod: · AWS_PROFILE=prod · unset AWS_ACCESS_KEY_ID …=).
  A NAME in both =:env= and =:unset= is =:env='s.

** Sessions

- =devops--inject-header-args= injects =:session= and =:async= as
  today, and =:dir= as the project root (=project-current=, else the
  org file's directory), or the scheme's =:dir= relative to it. It
  never injects the scheme name as =:dir=.
- =devops--session-name= names the pool by the target as written,
  followed by that directory, =devops:/aws:prod:/src/app/=: a session
  keeps the directory it started in, so two projects using
  =/aws:prod:= must not share one.
- =devops--execute-on-target= binds =process-environment= with the
  scheme's =:env= in front around the run, and each =:unset= NAME as a
  bare ="NAME"= (no ===), which is how =process-environment= marks a
  variable removed for the processes it starts. A session's shell inherits
  it when babel starts the session, so it holds for every block that
  session runs after: sh, bash, python, any session language. A live
  session keeps the environment it started with; after changing
  =devops-target-schemes=, kill its sessions. The README says so.
- A block can still =export AWS_PROFILE=other= inside the session, and
  that carries over. The reviewer sees it in the block; the README says
  so too.
- =:target nil= and a block's own =:dir= opt out as today.

** Shell DWIM

=devops-open-terminal-dwim= on a heading with a scheme target:

- opens a *local* terminal (=devops--open-terminal-at-dir=), in the
  same directory blocks run in, never through the
  =file-remote-p= branch;
- =unset=s the scheme's =:unset= first, then exports its =:env=, then
  the block's =:var= env vars, so a block's own variable wins as it
  does today. The terminal's login shell may set them again from its
  rc files; the README says so;
- copies a shell block's body to the kill ring, as today.

=devops--ghostty-command= takes the merged alist; a =(NAME . nil)=
pair becomes =unset NAME=.

** Tangle and drift

A scheme target is not a filesystem. =devops-tangle=, =devops-drift=
and =devops-visit-file= on it fail with =user-error "Target prod:
/aws:prod: is not a filesystem target"=, and =devops-tangle-all= skips
it with a message.

** Not in scope

- Schemes over a remote host (=/ssh:bastion|aws:prod:=): the scheme's
  environment is local.
- Credentials that are not environment (=aws sso login= state, a
  keychain prompt): the CLI handles them as it does today.
- Checking *who* a credential is (=aws sts get-caller-identity=) at run
  time. A package may add it; devops.el does not run it.

** Done when

- A block under =#+TARGET: prod /aws:prod:= prints =AWS_PROFILE=prod=
  with =env | grep AWS_=, in an async sh session and in python; a
  second target =/aws:dev:= runs in its own pool with its own value.
- =/aws:prod-admin:= with =:allow ("prod")= fails before a session
  starts; =/aws:../x:= fails the name syntax.
- A dynamic target yielding =/aws:prod:= runs the same way.
- With =AWS_ACCESS_KEY_ID= set in Emacs's =process-environment= and in
  the scheme's =:unset=, a block's =env= does not show it, in a new
  session and in a sync run; =devops-target-env= lists it as =(NAME
  . nil)=; DWIM's command has =unset AWS_ACCESS_KEY_ID= before the
  =export=s.
- No TRAMP function sees a scheme name: a test with
  =tramp-file-name-handler= advised to signal never trips.
- =devops-open-terminal-dwim= on the heading builds a local ghostty
  command exporting =AWS_PROFILE=prod= then the block's vars
  (=devops--ghostty-command= is the pure part to test).
- =devops-tangle= on the heading fails with the message above.
- =make compile= and =make test= pass on Emacs 30.1; an example in
  =examples/=; README section.
